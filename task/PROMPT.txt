为内部审计报告做离线发布审核器。案例声明有限域变量，每个变量取 0 或 1，约束只允许若干变量和的闭区间上下界；受保护变量和公开事实由输入标记。候选披露由带收益的原子项组成，每项携带一个等式及目标角色节点。角色继承图是 DAG；角色能看到自己和祖先节点的披露。审查还显式列出可以联合阅读的角色组，组看到其成员可见项的并集。相同等式由不同原子项发布时按等式语义合并，收益仍按选中项计。所有值来自同一个输入见证赋值，校验该赋值满足基础约束和每项披露。
audit 输出指定选项集下的每个角色及角色组、每个受保护变量是否仍有 0 和 1 两种可行解释，并分别给出按变量 ID 排序的字典序最小见证。公开事实已让某变量固定时，将它报告为基础输入已泄露，并禁止发布任何选项。若联合披露新固定某变量，另给最小基数的可见原子项子集，按升序项 ID 列表决胜，空集和重复等式都要正确处理。optimize 在全部角色和联合组过审的前提下最大化总收益，其次最少披露项，再按项 ID 列表字典序选唯一解，返回赢家的完整审查。
支持 18 个变量、22 个披露项，说明如何复用可行赋值集合并裁剪选择空间。测试覆盖两个角色单独安全但合并后固定一位、继承菱形、冗余约束导致更短解释、同收益破平及无任何可行基础模型。小规模结果用独立枚举核对。

在上述统一模型中加入增量发布，不能假设已公开内容可以撤回。输入按提交号提供基础事实扩充和每轮候选项，各轮历史已发布集合必须保留，历史发布时不知道的交互风险可以揭示，但不得改历史回执。每个受保护对象可是一位布尔值或一对有序布尔值；对每组阅览人给出必须仍可行的受保护取值组，并列出额外条件档案。一个档案由可见人已知的附加等式组成，仅当基础事实与该档案共同可行时才参加审查。即使整体上每一位仍同时可取两值，也必须挡住任何档案下某个要求取值组合消失的发布。若累计历史已经不安全，输出历史泄露及首次暴露的发布轮、接收组合和最小致泄露项；不能把历史项移出修复。把 optimize 扩为逐轮事务式 publish，提交时对事实版本、角色图版本及累计披露基线一起做并发复核，保存选择和证明回执，失败整轮不改变披露集合；同时支持以前的版本按当时事实、角色图查询。至少给出一个逐轮分别安全但累计不安全、以及一个两位分别可能但联合取值被排除的独立断言。

使用 Windows 原生 Python 3.12、标准库和 CPU，从空仓库实现，所有夹具用本地虚构数据。命令格式为 python -m solution <命令> CASE.json，涉及持久状态的命令带 --db DB.sqlite。标准输出为 UTF-8 JSON，同一逻辑输入产生同一结果；结构错误给出可定位的错误码及字段位置。交付可直接运行的样例、README（含完整输入输出定义与复现命令）和可用 python -m unittest discover -s tests -v 执行的断言测试。
